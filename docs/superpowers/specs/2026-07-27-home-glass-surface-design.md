# 朗世乐主界面与 Glass Surface 设计规格

## 状态与范围

本规格记录用户在 2026-07-27 明确选择的方案 A，用于实施计划 Task 5。范围仅包含首页视觉骨架、共用 Glass Surface、游戏栏、六个服务入口、底部导航和服务占位页；实验控制面板、HUD、粒子与动作系统仍属于 Task 6。

## 设计目标

- 在真实移动 WebView 中构造人物被多层半透明玻璃遮挡的复杂场景，为四种 Blur 实现提供公平的性能测试载体。
- 保持毛玻璃、半透明、极简和轻立体感，但避免普通表面大面积发光。
- 保持移动触摸可用性、语义可访问性和 GitHub Pages 子路径部署兼容性。

## 选定方案

采用单一 React/DOM 结构。`GlassSurface` 只根据 `GlassMode` 切换模式类和 `data-glass-mode`，不为四种模式分别渲染页面，也不改变内容、布局、图片或交互树。

未采用的方案：

- 每种 Blur 使用独立组件：样式隔离直观，但 DOM 差异会污染性能对比。
- Canvas 主导界面：视觉自由度高，但会削弱语义可访问性并改变本次要测量的 CSS/WebView 玻璃场景。

## 视觉构图

首页占满移动视口，使用深石墨与去饱和青绿色环境。用户提供的战术人物作为独立背景层，人物上半身保持清晰，下半身被游戏栏、服务网格与底栏玻璃覆盖。暖香槟色仅用于当前选中状态、焦点和少量图标强调。

从上到下的布局为：

1. 安全区内的品牌与紧凑状态区域，品牌文案固定为“朗世乐”。
2. 低高度、细长的四游戏栏，高度目标为 50–56px。
3. 十二列网格组织的六个非正方形服务入口，宽高与跨列数有变化，不做等大方块。
4. 固定在底部安全区上方的五项导航。

普通玻璃仅使用半透明填充、中性细边框、内高光、阴影与噪点，不使用发光边缘。只有当前选中的游戏和底栏项可以使用 `selected-glow`。所有图标使用代码原生 SVG 线性图标，不引入未经授权的游戏 Logo 素材。

## 组件边界

### `App`

持有当前 `ExperimentSettings` 和首页的低频交互状态，将 `glassMode` 传入页面。Task 5 不新增高频 RAF 状态。

### `HomeScreen`

组合人物背景、品牌、`GameRail`、`ServiceGrid`、`BottomNav` 与 `ExperimentalPlaceholder`。它只负责页面编排，不实现具体玻璃算法。

### `GlassSurface`

为所有玻璃区域提供唯一表面结构。输入为 `mode: GlassMode`、可选 `selected` 和标准 HTML 属性；输出始终是同一种元素树，并提供：

- `data-glass-mode="real|simulated|preblur|off"`
- `data-selected="true|false"`
- 基础类 `glass-surface`
- 唯一模式类 `glass-surface--<mode>`
- 仅在 `selected` 时存在的 `glass-surface--selected`

模式语义：

- `real`：使用 `backdrop-filter`/`-webkit-backdrop-filter`。
- `simulated`：使用半透明渐变、噪点和高光模拟玻璃，不使用 backdrop blur。
- `preblur`：让表面引用同一人物素材的预模糊背景层；保持内容结构不变。
- `off`：关闭模糊，只保留可读的半透明深色表面。

### `GameRail`

固定显示“三角洲行动”“CS2”“Valorant”“Steam 游戏”。默认选中“三角洲行动”。只有选中项显示近似几何图标，未选中项只显示文字；使用 `aria-pressed` 和选中数据属性表达状态。

### `ServiceGrid`

固定显示“趣味单”“小时单”“自助下单”“客服接待”“活动专区”“全部服务”。每项是至少 44px 高的按钮，使用不同列宽和高度形成有节奏的非正方形网格。激活任一服务后显示 `Experimental / Mock` 占位层，并保留明确关闭操作。

### `BottomNav`

固定显示“首页”“挑选”“订单”“消息”“我的”，默认“首页”使用 `aria-current="page"`。Task 5 仅切换可见选中状态，不引入真实业务路由或数据。

## 状态与数据流

`App` 创建默认设置并把 `settings.glassMode` 向下传递。所有 `GlassSurface` 接收同一个模式值，因此一次只激活一种 Blur 实现。游戏、服务占位层和底栏的选择状态保留在相应低频 React 状态中；任何点击都不重建四套页面。

服务入口没有后端请求、用户身份、订单或真实业务数据。占位层只显示被选择的服务名称与 `Experimental / Mock` 标记。

## 响应式与可访问性

- 页面最窄支持 320px；Task 7 将集中验证 375×812、390×844、393×852、430×932 和 844×390。
- 固定底栏使用 `env(safe-area-inset-bottom)`，正文为其预留空间，禁止横向溢出。
- 所有按钮具有可见文字或可访问名称，触摸目标使用至少 44px 的命中类。
- 图标标记为装饰性时不重复朗读；焦点态使用现有暖色轮廓令牌。
- `GlassMode` 不通过隐藏副本实现，避免读屏器遇到重复内容。

## 降级与错误处理

- 浏览器不支持 `backdrop-filter` 时，`real` 模式仍通过深色半透明填充保证文字对比度；能力状态由后续实验面板展示，不在首页伪造支持。
- 人物或字体加载失败时，背景色和系统字体回退仍保证界面可操作。
- 服务占位层关闭后恢复首页状态，不修改实验设置。

## 测试与验收

Task 5 使用 Vitest 与 React Testing Library 先写失败测试，再实现：

- 品牌精确为“朗世乐”。
- 恰好四个游戏，只有选中“三角洲行动”显示近似图标。
- 六个服务和五个底栏文案精确匹配规格。
- 每个服务入口具有 44px 命中类，并能打开可见的 `Experimental / Mock` 占位层。
- 四种模式渲染同一 DOM 子树，差异仅限模式类和 `data-glass-mode`。
- 普通 Glass Surface 不包含 selected glow 类，选中项才包含。
- 控件没有重复角色、缺失名称或不可访问的纯图标按钮。

Task 5 完成门禁为相关测试、TypeScript、ESLint 与生产构建全部通过。视觉视口、横屏、微信 UA、截图对照和真实 Pages 验证在 Task 7 统一执行。

## 非目标

- 不实现真实下单、客服、消息、订单或账户功能。
- 不引入服务器、分析 SDK 或远程报告上传。
- 不实现 Task 6 的实验面板、HUD、Benchmark UI、粒子或触摸视差。
- 不创建正式 Release、标签或纯 SemVer 发布。
